# مراجعة إصلاح CSP للتنقل — 2026-10-22

## المشكلة والإصلاح

Lighthouse على Production كان يسجل حجب JSON الخاص بقواعد التحميل المسبق في `dart-navigation.min.js`، وتقييم Best Practices أصبح 92. تملك الصفحة الرئيسية قاعدة فورية لصفحة المنتجات بالإضافة إلى قاعدة الروابط، بينما تستخدم باقي الصفحات قاعدة الروابط فقط.

أضيفت بصمتا SHA-256 للمحتويين الفعليين إلى `script-src` داخل `vercel.json`. بقيت آلية التنقل والتحميل المسبق وسلوك Save-Data كما هي. لم يضف الإصلاح `unsafe-inline` أو `unsafe-eval`، وتبقى سمات JavaScript داخل HTML محجوبة.

المرجع: [Chrome — Speculation rules and Content Security Policy](https://developer.chrome.com/docs/web-platform/prerender-pages#speculation-rules-and-content-security-policy).

| قاعدة البيانات وAPI | لا Migrations أو تعديلات Schema أو Endpoints |
| التحقق من البصمات | الاختبار يشغل مصدر التنقل ونسخته المضغوطة على `/`, `/index.html`, `/products.html`, `/about.html` ويحسب بصمة JSON الناتج؛ فشل قبل الإصلاح ونجح بعده |

| التصفح | اختبار التنقل يستخدم CSP الفعلية ويرفض أي مخالفة أثناء سيناريو التنقل. يغطي الصفحة الرئيسية والمنتجات والعودة والفلاتر والسلة وSave-Data |
| الاختبارات المحلية | 31 مجموعة `ciStatic` ناجحة. اختبار التنقل ناجح في headless shell؛ فحص استعادة BFCache الكامل يبقى مطلوبًا في Chromium الكامل على CI |
| أحجام التحميل | لا تغييرات في ملفات JavaScript أو CSS التي تصل إلى العميل |
| النشر | Commit عادي على `main`؛ التعديل يخص الموقع، لذلك يفترض أن يتخطى مشروع الـAPI البناء بحسب الملفات المتغيرة |

## التجربة والتراجع

بعد النشر افتح Home ثم Products وAbout، وتأكد من عدم وجود مخالفة CSP تخص speculationrules في Console. جرّب الرجوع والتقدم والفلاتر، ثم راجع Lighthouse على الموبايل والكمبيوتر. يظل التقييم متغيرًا حسب بيئة القياس؛ نجاح تصحيح المخالفة لا يعتمد على تخفيف حدود الاختبار.

التراجع يكون بـGit revert لهذا الإصلاح وإعادة نشر الموقع، ولا توجد خطوات قاعدة بيانات.
