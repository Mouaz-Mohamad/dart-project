# استعادة كلمة سر العميل — 3 نوفمبر 2026

الزر والمساران موجودان بالفعل. الاستعادة الحالية تستخدم كود بريد إلكتروني من ستة أرقام؛ لا تغير هذه الدفعة الطريقة إلى رابط.

## الإصلاح

- إصلاح CSS الذي كان يعرض نموذج طلب الكود ونموذج تغييره معًا رغم `hidden`؛ تأكد ظهور المشكلة في المتصفح على الموقع قبل التعديل.
- مطابقة حد العميل الأدنى مع سياسة الخادم الحالية: 6 أحرف؛ المندوب يحتفظ بحده 12. الخادم يعيد التحقق من سياسته.
- منع الضغط المتكرر أثناء الإرسال والحفظ، مع حالات انتظار وأخطاء واضحة دون عرض تفاصيل داخلية.
- إعادة الإرسال تبدأ طلبًا جديدًا وتمسح الكود وكلمة السر من النموذج. الرد المتأخر بعد الإغلاق أو فتح حساب آخر لا يغير الحوار الجديد.
- بعد النجاح يختفي نموذج تغيير كلمة السر وتظهر العودة إلى Login مع ملء معرف الحساب فقط. تمسح كلمة السر والكود عند النجاح والإغلاق.
- دعم Escape وحصر تنقل Tab داخل الحوار وإعادة التركيز بعد إغلاقه.
- إصلاح الدالة العامة `requestPasswordReset` لتستخدم API الحقيقي بدل مسار محلي قديم لم يكن موصولًا بطلب الخادم.

## الملفات والعقود

- المصدر: `src/storefront/platform/authentication.js`؛ ملفات التسليم المولدة: `Js/dart-platform.js` و`Js/dart-platform.home.min.js`.
- الاختبارات: `tests/password-reset-runtime.cjs` و`backend/tests/password-reset.test.ts`، مع ربط الأول بقائمة الاختبارات وFrontend CI.
- لا migrations ولا تعديل لعقود الخادم. المساران الحاليان: POST `/api/v1/auth/forgot-password` وPOST `/api/v1/auth/reset-password`.
- ولّد البناء المحلي CSS/home.css وCSS/home.min.css من المصادر الموجودة للفحص؛ هما قديمان عن المصدر أصلًا على main، ولم تُضمَّن أي تغييرات CSS في هذه الدفعة. CI وVercel ينفذان البناء قبل الفحوص.

## التحقق

- `npm run build`: ناجح، بما فيه staging للأصول ذات الإصدارات.
- `npm run check` بعد البناء: 41 فحص واجهة ناجحًا؛ فحص المصدر وميزانية الأداء ناجحان.
- `cd backend && npx vitest run tests/password-reset.test.ts tests/identity.routes.test.ts`: 19 اختبارًا ناجحًا.
- `cd backend && npm run lint && npm run typecheck`: ناجحان.
- `node tests/database-authoritative-storage.cjs` و`git diff --check`: ناجحان.
- اختبارات الحوار تستخدم DOM/API doubles. اختبارات الخدمة تستخدم PostgreSQL معزولًا عبر PGlite؛ لا تعدل بيانات الإنتاج ولا ترسل بريدًا حقيقيًا.
- حالات الاختبار: كود صحيح/خاطئ/منتهي، حد المحاولات، منع إعادة الاستخدام، إعادة الإرسال وإبطال القديم، منع كلمة سر سابقة أو قصيرة، قبول 6 أحرف للعميل، تسجيل الدخول بالجديدة وفشل القديمة، إلغاء الجلسات، سجل التدقيق، وعدم كشف وجود حساب أو إرسال كود لحساب غير موجود. واجهة: إدخال ناقص، عدم تطابق، ضغط مزدوج، رد متأخر، خطأ اتصال، تنظيف الحقول، Tab وEscape والعودة للدخول.
- فحص وصول رسالة حقيقية إلى Inbox أو Spam غير منفذ؛ وجود إعدادات SMTP لا يثبت التسليم. لم يتغير إعداد إرسال البريد.
- اختبار بصري على هاتف فعلي أو أحجام محاكاة متعددة غير منفذ.

## طريقة التجربة اليدوية

افتح صفحة Login واضغط Forgot password، ثم أدخل الإيميل المسجل أو الهاتف أو معرف الحساب. يظهر نموذج طلب الكود وحده، وبعد نجاح الطلب تظهر خانة الكود وكلمة السر الجديدة وتأكيدها. ابحث عن الرسالة في Inbox وSpam. أدخل الكود واختر كلمة سر جديدة ثم Back to Login. تحقق من الدخول بالجديدة ومن رفض القديمة. إعادة الإرسال تلغي الكود السابق؛ استخدام الكود الناجح مرة ثانية يُرفض.
