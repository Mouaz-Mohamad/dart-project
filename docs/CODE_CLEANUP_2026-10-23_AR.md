## أدلة المحافظة على السلوك

- مقارنة Acorn AST لنسختي الداشبورد ومنصة العميل قبل/بعد التنظيم أعطت تطابقًا بعد تجاهل التعليقات ومواقع النص فقط.
- المقارنة نفسها لملفات التسليم المضغوطة المعدلة: News، Sets، Home UI وHome Platform أعطت تطابقًا.
- مقارنة أجسام الدوال عبر TypeScript AST: 32 Method بقيت أجسامها كما هي تمامًا، بما فيها كل أوامر الكتابة والمعاملات. أجسام عمليات القراءة السبع المنقولة متطابقة بعد استبدال `this.pool` بوسيط `pool` فقط.
- أجسام الدوال الحسابية الـ12 المنقولة متطابقة. أُبقيت التصديرات العامة السابقة من `commerce.service.ts` لتوافق المستوردين.
- لا تحتوي ملفات `commerce.*-queries.ts` على SQL للكتابة.
- فحص الأداء مرّ ضمن الحدود الحالية دون زيادتها: Home المباشر 225KiB، ومجموع Core نحو 963KiB، والمصادر ذات التحميل الخاص نحو 437KiB. هذه مجاميع اختبار المستودع وليست قياس تحميل شبكة المستخدم.

## التحقق

- `npm run build`: إعداد CSS وJavaScript ونسخة HTML للنشر نجح.
- `npm run check`: فحص المصادر و32 فحص واجهة ثابتًا نجح.
- `npm --prefix backend run check` و`build`: Lint وTypeScript والبناء و435 اختبارًا نجحت؛ 47 اختبار PostgreSQL مستقلًا لم تُشغل محليًا لعدم إعداد قاعدة اختبار مستقلة. لم تُجر اختبارات كتابة على بيانات الإنتاج.
- أضيفت 7 حالات تحقق لأوامر القراءة: تعارض إصدار الطلب، البيانات الفارغة، فشل القاعدة مع rollback/release، الإصدار الافتراضي، رفض عميل غير موجود في Snapshot/Tracking، وترتيب محطة التوصيل الحالية دون تعديل مصفوفة المدخل.
- أضيف فحص ملكية المصادر وترتيبها وصحة الوحدات وتطابق الناتج وربط `src/**` بـFrontend CI، مع إبقاء حالات الاختبارات الحالية عند تحديث مسارات المصادر.
- مجموعات المتصفح المحلية العشر نجحت: Dashboard groups، الموقع العام، Home، التنقل، News، Waiting، محرر Sets، Home Sets، متجر Sets، وإعدادات المتجر. بيئة التشغيل المحلية تستخدم Chromium Headless Shell؛ لذلك الاستعادة الفعلية من BFCache لا تثبت محليًا وتظل مطلوبة في اختبار CI بمتصفح Chromium الكامل. لا يوجد تغيير مرئي مطلوب في هذه الدفعة.
- صُحح انتظار واحد في اختبار News ليتحمل اختفاء الصف مؤقتًا أثناء إعادة تحميل الصلاحيات؛ يظل الاختبار يشترط ظهور الصف الجديد وأن يكون زر Edit مخفيًا فعلًا. كود التطبيق لم يتغير لهذا السبب.
- يُعاد اختبار PostgreSQL وChromium الكامل تلقائيًا على GitHub بعد الرفع؛ تُراجع نتائج Check Runs وحالة نسختي الإنتاج قبل اعتبار الدفعة منشورة بنجاح.
