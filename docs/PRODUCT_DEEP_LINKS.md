# Product deep links & search discovery — Dart | for you

Dart keeps its existing fast product Modal while exposing stable, crawlable URLs and server-authoritative sitemap discovery for every active model.

## URL contract

- Collection: `/products`
- Model: `/products/<model-name>--<model-code>`
- Example: `/products/cairo-wide-leg-jeans--dw-101`
- Legacy collection URL: `/products.html` permanently redirects to `/products`.

The model code suffix is the stable lookup key. If the product title changes later, an older URL can still resolve to the same model by its code and the runtime publishes the newest URL as canonical.

## Runtime behavior

1. Clicking a product card opens the current Modal exactly as before.
2. The browser URL is updated with `history.replaceState`; there is no reload and no second product-data request.
3. Closing the Modal uses the existing browser-history behavior and returns to `/products`.
4. Opening a deep link directly loads `products.html` once through the Vercel rewrite, waits for the server-authoritative catalog, and opens the requested Model in the same Modal.
5. Back/Forward navigation replays the Modal state without forcing a page refresh.
6. Product titles remain crawlable `<a href>` links; card images receive descriptive alt text from the real product title/category.

## Search metadata

The home and collection metadata use the real brand aliases naturally: `Dart`, `Dart for you`, `Dart Wear`, and `دارت`, together with Egyptian menswear terms such as `لبس رجالي` and `لبس شبابي`. We deliberately do **not** add a `meta keywords` tag or make unsupported claims such as “أفضل براند”.

When a model route is active, the runtime publishes a model-specific title, description, canonical URL, Open Graph/Twitter product values and schema.org JSON-LD. Models with color/size options use `ProductGroup` + `Product` variants with:

- Brand: `Dart | for you`
- Alternative brand names: `Dart Wear` and `دارت`
- stable model code / variant SKU
- current price in EGP
- variant stock availability from the already hydrated public catalog
- color-specific image when available
- `BreadcrumbList` from Dart → Products → Model

## Sitemap architecture

`/sitemap.xml` is now a sitemap index with two children:

- `/sitemap-pages.xml` — static public pages.
- `/product-sitemap.xml` — dynamic product URLs generated by the Backend from `CatalogService.publicCatalog()` / PostgreSQL-authoritative catalog data.

The dynamic sitemap includes only active public models already allowed by the public catalog query. It uses the same slug algorithm as the storefront, publishes `lastmod` from each model update time, and is cached briefly at the API/CDN layer so catalog changes become discoverable without hand-editing XML.

## Performance and safety rules

- Deep linking never replaces the Modal with page-to-page navigation.
- Product sitemap data comes from the Backend, not LocalStorage or client-supplied prices/stock.
- Private/admin pages stay excluded from the sitemap and retain `noindex` rules.
- Search copy is descriptive rather than keyword stuffing.
