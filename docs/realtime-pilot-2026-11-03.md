# تجربة التحديث المباشر — Dart — 3 نوفمبر 2026

> تحديث القرار: بناءً على طلب المالك، تم استبعاد مزوّد الرسائل الخارجي والحساب الإضافي. هذه وثيقة التجربة الأولى التاريخية؛ الخطة الحالية ونتائج PostgreSQL → SSE في `direct-realtime-pilot-2026-11-03.md`. إعداد Ably أدناه لم يعد مطلوبًا للمسار الحالي.

**الحالة: تجربة معزولة مكتملة، وليست تفعيلًا للتحديث المباشر في الإنتاج.** لم تتغير طلبات التحديث الدورية في المتجر أو الداشبورد، ولم يُنشأ حساب أو اشتراك مدفوع. النقل في التجربة محاكاة محلية لمزوّد الرسائل؛ لم يتصل الاختبار بخدمة Ably الحقيقية.

## ما نُفّذ

- تشغيل مخطط قاعدة البيانات الحالي داخل PostgreSQL/PGlite معزول، وتنفيذ `CommerceService.checkout` الحقيقي لإنشاء أوردر تجريبي بقطعة محجوزة. لا توجد كتابة في قاعدة العملاء.
- التقاط إصدار الطلبات بواسطة trigger تجريبي داخل معاملة الحفظ نفسها. التراجع عن المعاملة يلغي الحدث معها، وإعادة checkout بنفس مفتاح idempotency لا تنشئ أوردرًا أو حدثًا ثانيًا.
- سجل أحداث منفصل عن رسائل البريد/واتساب، مع claim ذري وlease محدودة وfencing، وإعادة محاولة محدودة، وحالة تبين تراكم الأحداث أو استنفاد المحاولات. إعادة النشر تستخدم معرّف الحدث نفسه.
- حالة عميل قابلة لتبديل وسيلة النقل: اشتراك قبل جلب اللقطة، دمج الإشعارات، تجاهل القديم والمكرر، استدراك بعد reconnect/foreground، وإلغاء الردود المتأخرة بعد تسجيل الخروج. لا توجد قراءة دورية أثناء الاتصال السليم؛ فشل الجلب يعاد بمحاولات متباعدة ومحدودة المعدل.
- endpoints تجريبية للقراءة فقط تستخدم middleware الجلسات وMFA وصلاحية `orders.read` الحالية. غير مركّبة في تطبيق الإنتاج.
- موصل Ably REST جاهز لاختبار حساب مهيّأ صراحةً؛ مفتاحه يبقى خادميًا، وعنوان الخدمة ثابت، والمهلة محدودة، والرسالة لا تحمل أسماء أو أرقام هواتف أو عناوين أو تفاصيل أوردر. لم يُستخدم هذا الموصل للاتصال بمزوّد حقيقي.

الملفات موجودة في `backend/experiments/realtime-pilot/`، واختباراتها في `backend/tests/realtime-pilot.test.ts`. السكريبت يرفض التشغيل في Vercel أو `NODE_ENV=production` أو مع `DATABASE_URL` / `TEST_DATABASE_URL`؛ لا يقرأ `.env`. ملف SQL ليس migration إنتاجية ولا يُطبّق تلقائيًا.

## ما يلزم قبل الإنتاج

1. ربط حساب Ably تجريبي وضبط مفاتيح محدودة الصلاحية على الخادم، دون وضعها في المحادثة أو كود المتصفح. لم تظهر وصلة Ably متاحة في التطبيقات المتصلة أو نتائج البحث عنها.
2. تجربة النقل الفعلي وSDK العميل وإصدار التوكنات من جلسات Dart، واختبار سحب صلاحية اشتراك قائم. المحاكاة تعيد فحص الأهلية قبل كل إرسال؛ هذا **لا يثبت** آلية سحب توكن Ably الفعلية.
3. تحديد وتشغيل الناشر فور commit مع إعادة محاولة دائمة مستقلة ومراقبة تأخره؛ التجربة تشغله صراحة بعد checkout، ولا يوجد عامل إنتاجي دائم مركب هنا. اتصال العميل وحده لا يكشف تعطل الناشر.
4. تأكيد قاعدة الإنتاج والوصول إليها، ثم اعتماد migration مضبوطة واحتفاظ/تنظيف لسجل الأحداث؛ لا تُطبَّق fixture SQL على الإنتاج.
5. قياس نقل الشبكة والزمن والحصص والتكلفة الحقيقية، ووضع حدود اتصالات ورسائل وميزانية. لا تزال مقارنة تكلفة Ably/Neon غير منفّذة.
6. بعد القبول، توصيل جزء واحد من الداشبورد وتعطيل poll الخاص به أثناء push السليم، ثم التوسع تدريجيًا. الأقسام الأخرى وGPS تبقى خارج هذه التجربة.
