# News implementation and verification

News uses shared 70vw cards on Home (after products) and About (after the brand story), on both phones and desktop as explicitly requested. Covers retain a 3:4 portrait ratio. Burgundy section headings match Sets with a 2px left border and 12px spacing; cards add subtle shadows, publication dates, larger headlines and three-line excerpts. The horizontal carousel retains touch scrolling, mouse dragging, arrow controls and five-second automatic movement. Interaction, hidden pages, open dialogs and reduced-motion preferences pause automatic movement.

Read full story is a real anchor. A normal click opens the 90vw × 90dvh reader (90vh fallback), with a 40px X and a bottom Done button. Phone Back, Escape, backdrop clicks, X and Done consume the same modal history step and restore focus and the underlying page position. Forward reopens the article without another history entry. Reader padding clicks stay inside the reader. Ctrl/Cmd-click and opening in a new tab follow the real article URL. Private dashboard previews keep the dashboard URL and recheck centralized Staff permissions when reopened.

Each published article has `/news/<original-news-id>/<title-slug>`. The opaque ID preserves its case and remains stable; changing the title redirects old slugs to the current canonical URL. Direct visits and reloads return the full article HTML, cover, author (Dart), publication date and reading-time estimate, without depending on JavaScript. Canonical, Open Graph, Twitter and NewsArticle data describe the real article. Unknown/draft/archived articles return 404/noindex; upstream failures return safe 503/noindex pages. Article and sitemap responses use no-store so an archived publication is not retained in a CDN stale cache. Actual Google indexing remains Google's decision.

`/news-sitemap.xml` reads every public API page, deduplicates stable IDs and is included in the existing sitemap index. Invalid pagination or an upstream failure returns 503 rather than a misleading partial sitemap; the empty state returns a valid empty XML sitemap. The current public API does not expose modification times, so the implementation does not invent dateModified or lastmod values. No database migrations, backend changes, new staff grants or News write endpoints are needed for this presentation/SEO batch.

Dart Eye → News follows the existing First / Second / table layout. First contains search, publication/archive filters and Add News; Second contains Delete selected. Delete archives records and removes them from public APIs; Restore retains their original draft/published status. Manual Order values come first, then newest publications. Empty Order uses newest-first behavior. Blank Excerpt uses the start of Full News.

## Files and database

- `Js/dart-news.js`, `CSS/main.css`, `CSS/responsive.css`, `index.html`, `about.html`: shared carousel and reader. `CSS/home.css` / `CSS/home.min.css` are generated by the existing build.
- `Js/dart-news.js` is a small loader; `Js/dart-news-runtime.js` downloads near the carousel. In Dart Eye, both the reader and `Eye/dart-news-admin.js` download only when an authorized Staff member opens News. Failed module downloads have a retry action.
- `Js/dart-news-links.js`: one deferred URL/date utility, shared with Node SSR; the initial page never eagerly loads the News helpers or full reader.
- `api/news-page.js`, `api/news-template.html`, `CSS/news-article.css`: independent public article renderer/template/styles. `api/news-sitemap.js`, `sitemap.xml`, `vercel.json`: live public discovery and routing; static template explicitly bundled into its function.
- `Eye/dart-news-admin.js`, `Eye/dart-news.css`, `Eye/Dart Eye.html`: permissioned management, editor, image compression, pagination and archive actions.
- `backend/src/modules/news/`: strict contracts, permissioned routes and transactional service; wired in `backend/src/application.ts` and `backend/src/app.ts`.
- `backend/migrations/0059_news_foundation.sql`: independent table, public-order index, RLS and News permissions. It creates no sample articles and changes no commerce records.
- `backend/openapi.yaml`, `docs/API_CONTRACT.md`: complete new route and field contracts.

`news.read` allows private previews; `news.manage` allows writes. Owner receives both; other Staff require explicit grants through Settings. Writes use the existing session, CSRF and configured MFA controls. Server-side versions and row locks prevent stale overwrites; successful content/state changes record before/after audit values. Repeated identical creates and archive/restore actions are safe. Image retries reuse the same in-memory asset ID, and logout invalidates pending editor results. News is not persisted in browser storage.

Migration `0059_news_foundation.sql` was applied to the production Neon main branch on 2026-10-08 after verification of all 58 existing checksums. Its recorded SHA-256 is `ef27706eb3f50f773d45f06f31512f216bcc6062954e6fb69645a569fcaf921c`; the initial News table is empty.

## Manual end-to-end check

1. Sign into Dart Eye as Owner (refresh the session after the migration), open News and choose Add News. Supply a cover, title and Full News; save as Draft. Verify the dashboard preview and confirm it is absent on Home/About.
2. Edit to Published. Check Home after products and About after brand story on desktop and phone. Verify 70% viewport card width, 3:4 cover proportions, date, arrows, swipe/drag and five-second movement. Move the pointer outside the carousel and remove keyboard focus to resume automatic movement.
3. Choose Read full story; verify 90% viewport width/height, complete text, inset margins, bottom Done, X/Escape/backdrop and phone Back closing only News. Test Forward and confirm the original page/focus/scroll return. Content containing HTML is displayed as text. Open the anchor in a new tab or reload its URL: the standalone article must show the full body without JS, including its canonical metadata. Update its title and confirm the old URL redirects. Archive it and confirm both its direct URL (404) and sitemap visibility change.
4. Save multiple published records: blank Order sorts newest first; numbers sort ascending ahead of automatic records. Test search and status filters.
5. Select a row and use Delete. It disappears from the public site and appears under Archived in News. Use Restore and confirm it returns if previously published.
6. Open the same article in two sessions, save one, then save the stale editor. Verify the conflict message and Reload latest News. A read-only Staff account may preview but cannot add, edit, upload or archive.
