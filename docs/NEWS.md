# News implementation and verification

News uses one shared 187.5×250px portrait card on Home (after products) and About (after the brand story). The horizontal carousel supports touch scrolling, mouse dragging, arrow controls and five-second automatic movement. Interaction, hidden pages, open dialogs and reduced-motion preferences pause automatic movement. Read more opens a large article dialog, fullscreen on mobile, with one cover and plain text.

Dart Eye → News follows the existing First / Second / table layout. First contains search, publication/archive filters and Add News; Second contains Delete selected. Delete archives records and removes them from public APIs; Restore retains their original draft/published status. Manual Order values come first, then newest publications. Empty Order uses newest-first behavior. Blank Excerpt uses the start of Full News.

## Files and database

- `Js/dart-news.js`, `CSS/main.css`, `CSS/responsive.css`, `index.html`, `about.html`: shared carousel and reader. `CSS/home.css` / `CSS/home.min.css` are generated by the existing build.
- `Js/dart-news.js` is a small loader; `Js/dart-news-runtime.js` downloads near the carousel. In Dart Eye, both the reader and `Eye/dart-news-admin.js` download only when an authorized Staff member opens News. Failed module downloads have a retry action.
- `Eye/dart-news-admin.js`, `Eye/dart-news.css`, `Eye/Dart Eye.html`: permissioned management, editor, image compression, pagination and archive actions.
- `backend/src/modules/news/`: strict contracts, permissioned routes and transactional service; wired in `backend/src/application.ts` and `backend/src/app.ts`.
- `backend/migrations/0059_news_foundation.sql`: independent table, public-order index, RLS and News permissions. It creates no sample articles and changes no commerce records.
- `backend/openapi.yaml`, `docs/API_CONTRACT.md`: complete new route and field contracts.

`news.read` allows private previews; `news.manage` allows writes. Owner receives both; other Staff require explicit grants through Settings. Writes use the existing session, CSRF and configured MFA controls. Server-side versions and row locks prevent stale overwrites; successful content/state changes record before/after audit values. Repeated identical creates and archive/restore actions are safe. Image retries reuse the same in-memory asset ID, and logout invalidates pending editor results. News is not persisted in browser storage.

Migration `0059_news_foundation.sql` was applied to the production Neon main branch on 2026-10-08 after verification of all 58 existing checksums. Its recorded SHA-256 is `ef27706eb3f50f773d45f06f31512f216bcc6062954e6fb69645a569fcaf921c`; the initial News table is empty.

## Manual end-to-end check

1. Sign into Dart Eye as Owner (refresh the session after the migration), open News and choose Add News. Supply a cover, title and Full News; save as Draft. Verify the dashboard preview and confirm it is absent on Home/About.
2. Edit to Published. Check Home after products and About after brand story on desktop and phone. Verify 250px image height, 3:4 proportions, arrows, swipe/drag and five-second movement. Move the pointer outside the carousel and remove keyboard focus to resume automatic movement.
3. Choose Read more; verify the complete text, closing/focus return and fullscreen phone dialog. Content containing HTML is displayed as text.
4. Save multiple published records: blank Order sorts newest first; numbers sort ascending ahead of automatic records. Test search and status filters.
5. Select a row and use Delete. It disappears from the public site and appears under Archived in News. Use Restore and confirm it returns if previously published.
6. Open the same article in two sessions, save one, then save the stale editor. Verify the conflict message and Reload latest News. A read-only Staff account may preview but cannot add, edit, upload or archive.
