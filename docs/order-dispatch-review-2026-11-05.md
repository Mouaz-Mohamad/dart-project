# Physical dispatch confirmation

Approved flow: Preparing → Ready for Dispatch → Out With Representative → Representative On The Way → Delivered. External carriers go from confirmed Out With Representative directly to Delivered or the existing physical-return/inspection flow.

- Ready for Dispatch stores `legacy.pendingDispatch`. Courier work, live tracking and external tracking are not published yet. The warehouse may change assignment or roll back to Preparing without releasing order stock. Editing address/items requires returning to Preparing so a previous coverage review cannot silently authorize a different destination.
- Confirm Dispatch revalidates the saved courier/carrier, coverage, blocked governorate, current COD eligibility and inventory ownership. It requires the current order version, locks the order and commits status, assignment, inventory, audit and one outbound notification intent together. Assignment data cannot be changed implicitly in a confirmation request.
- New confirmed outbound orders cannot rewind to preparation or be cancelled as warehouse stock. Existing delivery interruption, refusal and carrier physical-return/inspection actions remain available. Route interruption keeps the first handover timestamp and does not queue another message.
- Existing outbound orders retain their status and assignments. Migration 0070 only extends the status constraint; it neither reclassifies old orders nor queues old notifications.

## Delivery semantics

One deduplication key per order: `order-whatsapp-dispatched:<order UUID>`. No request to Meta occurs in the order transaction. Existing durable delivery attempts prevent duplicate retries after accepted or unknown provider outcomes. A lost provider response requires reconciliation rather than automatic resend. Provider delivery/read receipts remain separate from queue publication.

Before sending, recheck active order/customer, original handover identity and recipient, outbound state and one-hour freshness. Suppress obsolete, delivered, refused, archived, deleted or expired notices. Notification failure does not undo physical dispatch. No real messages or customer orders are generated by the automated tests.
