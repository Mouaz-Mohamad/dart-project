## التحقق

- `npm run check` للواجهة: 35 فحصًا ثابتًا، ومنها الاختبار الجديد المربوط بـFrontend CI.
- `npm run build:js` و`npm run build` للواجهة، و`npm run audit:css -- --check`: ثبات المصدر والتسليم وميزانية التحميل، و0 تعارضات CSS محذوفة/مضافة.
- `backend: npm run check` و`npm run build`؛ اختبارات PGlite تستخدم schema معزولًا، وPostgreSQL 17 الفعلي في CI ينفذ أيضًا حالات التزامن واختبارات التكامل التي تتجاوز محليًا عند غياب قاعدة اختبار.
- `npm audit --omit=dev`: يجب أن يبقى بلا ثغرات معروفة. اختبارات SMTP تستخدم مزودًا تركيبيًا ولا ترسل بريدًا خارجيًا.
- فحوص Chromium الإحدى عشرة وتكافؤ CSS في CI على نفس commit؛ تنزيل Chrome محليًا أعاد ملفًا تالفًا، فلا يدّعي الفحص المحلي نجاح متصفح لم يعمل.
- قبل إعلان النشر: مراجعة GitHub Actions، ومطابقة commit في alias الواجهة والـAPI، وقراءة health والصفحات الأساسية وفحص رفض admin دون جلسة. لا كتابة أعمال في الإنتاج لمجرد الاختبار.

## تجربة يدوية في بيئة اختبار

1. جرّب حسابًا محذوفًا وآخر موقوفًا: لا دخول أو تجديد جلسة أو تعديل Profile بطلب قديم. يبقى تغيير البريد الطبيعي متاحًا للحساب النشط.
2. ألغِ طلبًا، ثم احجز قطعته في سلة أخرى: تعديل بيانات تواصله مسموح، وتعديل خصمه/قطعه مرفوض، وحجز السلة الثانية يبقى صالحًا.
3. سجّل أرقام Finance قبل/بعد أرشفة طلب مسلّم ومرتجع مكتمل: الإيراد والتكلفة والرد النقدي لا تتغير لمجرد الأرشفة.
4. استخدم إجماليًا 120.75: السلة والتتبع والمندوب والداشبورد تعرض القروش. مع قطعة محجوزة وقطعة حرة يمكن زيادة الكمية إلى 2؛ استبدل كودًا يدويًا ثم امسحه واضغط Apply لإزالته.
5. بعد فشل استلام رد طلب مكتمل، أعد تحميل الصفحة: يظهر رقم الطلب المؤكد دون إنشائه مرة أخرى. اختبر Back/Cancel لخصم مستهلك: لا يظهر متاحًا؛ يظل المرتجع الكامل داخل المدة مسار استعادته.
6. استخدم مزود بريد تركيبيًا: اتصال مرفوض يعاد بعد التعافي، وفقد إقرار الاستلام لا يعاد تلقائيًا ويظهر ضمن health حتى في دورة بلا أحداث جديدة.
